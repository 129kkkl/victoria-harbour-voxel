# 维多利亚港 · 体素数字沙盘（Victoria Harbour Voxel Sandbox）

Three.js r160+ / WebGL2，Vite + 原生 ES Module，全部程序化生成、种子化，
**不依赖任何外部在线地图 / 3D 资产 / 付费 GIS 数据**，安装后断网可运行。

## 运行

```bash
npm i
npm run dev      # 默认 http://localhost:5173
```

离线单文件版（双击即可运行，无需服务器 / 网络）：

```bash
npm run build:single   # → dist-single/victoria-harbour.html（约 0.8MB）
```

项目全部资产程序化生成（贴图 = Canvas 离屏、几何 = 种子化参数、零外部请求），
所以单文件化只是把 vite 的单 chunk JS 内联进 HTML（`tools/build-single.mjs`），
`file://` 协议下 WebGL2 / 模块脚本 / Canvas 均可用，已用 Edge headless 实测出图。

离线数值验收（全部不依赖浏览器 / GPU，直接跑与运行时同一份源码）：

```bash
npm run verify              # 地理 / 天文：8 项
npm run verify:city         # 城市层：30 项（天际线高度序列 / 地标落位 / 街道网格 / 城区剖面）
npm run verify:landmarks    # 地标精建：82 项，逐座从真实几何顶点量高度 / 收分 / 台阶 / 尖顶
npm run verify:fx           # 光影 / 天气：28 项（ACES 逆变换往返 / 天气过渡 / 路灯与障碍灯布点）
npm run verify:all          # 四项全跑
```

截图（需先 `npm run build && npm run preview`，由 Edge headless 跑真实 WebGL2）：


## M2 城市层是怎么长出来的

```
districts.js   17 个城区：中心经纬、半径、街道主轴角、街区尺寸、路宽、高度带、立面族
   ↓
streetGrid.js  在城区旋转坐标系里按 街区尺寸 + 路宽 切地块
               → 陆地/坡度/地标排除过滤 → 定高 → 分槽 → 产出 lot[]
               → 顺带沿网格线发出路面带（外圈人行道 0.10m + 内圈车道 0.22m）
   ↓
buildings.js   lot[] → 退台体量 + 裙房 + 屋顶设备 → 按立面族打包成 InstancedMesh
   ↓
facades.js     onBeforeCompile 注入世界尺度 UV：还原体量的米制局部坐标，
               每面墙按真实开间×层高重复；同段着色器解决
               ① 墙/顶混采样 ② 粗糙度+金属度读 MR 图 ③ 夜间窗光 = EM 掩码 × uNight
```

**为什么不用 Three.js 默认盒体 UV**：那样窗户会随楼体拉伸，30m 的楼和 300m 的楼窗格大小完全不同。
改用米制局部坐标后，玻璃幕墙每 1.5m 一竖梃、唐楼每 3.0m 一层窗，与真实建筑一致。

## M3 地标精建是怎么做的

地标是四棱台 / 三棱柱 / 圆台 / 球冠 / 斜杆 / 薄鳍的混合体，M2 那套"从 `instanceMatrix`
反推米制坐标"的 vertex shader **不成立**（它只对"单位盒体 + 实例缩放"有效）。所以 M3 改成
**在编译期就把米制 UV 直接写进几何**：

```
geo/landmarks.js          32 座的权威参数（经纬 / 高度 / 尺寸 / 朝向 / 立面族）
   ↓
landmarks/specs/*.js      每座一个 builder(C, L)：用局部坐标（dx 向东 / dz 向南 / y0 高度）
                          拼出各自的形态语言，并用 C.fact() 声明可量测的设计事实
   ↓
landmarks/prims.js        原语编译器：盒体 / 四棱台 / 三棱柱 / 圆台 / 球冠 / 圆环 / 斜杆
                          / 柱廊 / 台阶 → 按材质族合并的 BufferGeometry
                          UV = 沿该面水平轴的米制长度 + 该体量在地标局部系里的相位
   ↓
landmarks/plan.js         定位 + 落地高程（运行时与验收共用，保证两边量的是同一份顶点）
   ↓
landmarkBuilder.js        每材质族一个 Mesh；桅杆 / 拉索 / 钟面 / 屋顶设备合进一个顶点色材质
```

两个关键决定：

- **UV 相位对齐到整个地标**，而不是每段体量各算各的：一栋塔楼由几十个体量拼成，若每段都从
  `u=0` 起算，竖梃会在分段处错位。统一相位后，玻璃幕墙的竖梃从裙房一路贯通到塔冠。
- **杂项走顶点色**：桅杆、拉索、钟面、招牌、屋顶设备若"一种颜色一个材质"，draw call 会爆；
  合进一个 `vertexColors` 材质后，全部 32 座地标 + 缆车只占 **11 个 draw call**。

### 验收量测（`scripts/verify-landmarks.mjs`）

断言量的是 **`plan.js` 产出的真实 `BufferGeometry` 顶点**，不是回读 `landmarks.js` 的设计表 ——
所以"通过"意味着 builder 真的把楼建成了那个形状。量测本身踩过两个坑，都写进了
`landmarks/measure.js` 的注释：

| 指标 | 含义 | 怎么量 |
|---|---|---|
| `height` | 几何最高点 − ±0（含尖顶 / 桅杆） | 顶点极值 |
| `w@x%` | x% 高度处的水平截面跨度 | **用水平面切几何**取交线端点 |
| `taper` | 顶部 88% ÷ 塔身中段 35% 的跨度 | 分母用中段而非地面 |
| `steps` | 从下往上跨度每降 8% 记一级（退台数） | 32 级带采样 |
| `spire` | 最高点高出"仍有 55% 底宽"那一层的高度 | 轮廓回溯 |
| `peakAt` | 最宽处的高度占比（>0.45 = 飞碟 / 倒锥台） | 轮廓求极值 |

**为什么不用"找靠近该高度的顶点"量跨度**：塔楼侧壁是两个跨越 300m 的大三角形，中间根本没有
顶点，按顶点邻近采样会量出完全错误的截面。**为什么收分比的分母不用地面**：塔楼常带大裙房，
用地面跨度做分母会把裙房算进去，收分比严重失真。**为什么飞碟要看 `peakAt` 而不是 `taper`**：
倒锥台的最宽处在 60~80% 高度，88% 处已经收进屋面，`taper` 反而算出 < 1。

### 天际线高度序列（M2 / M3 核心验收）

从尖沙咀东望必须成立（`npm run verify:city` / `verify:landmarks` 逐条断言）：

```
ICC 484m  >  IFC 2座 415m  >  中银大厦 315m  >  时代广场/海富中心 216m
        >  恒隆广场 213m  >  力宝中心 186m  >  中环广场 181m  >  汇丰总行 60m
山体：太平山 552m（高于全部港岛建筑）
```

IFF 比例实测 1.317（真实 415/315 = 1.318）。ICC 坐标按公开资料核验为
22.30339°N, 114.16017°E；其余锚点为 ±150m 级近似，在 6.4km 视距下不影响判读。

**高度语义**：`landmarks.js` 里的 `h` 是**结构高度**，尖顶 / 避雷针 / 桅杆允许超出 ——
中银结构 315m、双桅到 367m；IFC2 结构 415m、桅杆到 448m。验收断言是
`h - 6 ≤ 实测总高 ≤ h + 70`，而不是硬性等于。

## M4 光影 / 夜景 / 天气是怎么做的

```
fx/tonelink.js    ACESFilmic 精确逆变换：显示色 → 线性 HDR（纯 JS，node 可验收）
                     天空 / 海面 / 雾的调色板仍是"按显示值手写"，运行时换算后
                     与城市层一起走 OutputPass 的 ACES+sRGB —— 一条链路到底
fx/postfx.js      EffectComposer：RenderPass（HalfFloat + MSAA×4 线性 HDR）
                     → UnrealBloomPass（阈值 1.0，强度随 nightF 0.15→0.75）→ OutputPass
fx/weather.js     四预设 × 8 参数（云量/压暗/雾倍率/日照倍率/雨强/湿度/风速），
                     Weather 控制器指数过渡；applyWetness / applyNightSpill 直接
                     作用于路面共享材质（湿路变暗变亮、夜间暖色溢光）
fx/rain.js        2400 根雨丝的 InstancedBufferGeometry：下落回收全在 vertex
                     shader（fract 相位循环），CPU 每帧只喂 4 个 uniform
city/streetLights.js  从 roads[] 四边形几何反推道路走向与路宽 → 两侧交替布灯
                     （isLand 过滤 + 网格去重）→ 光池 InstancedMesh + 灯头 Points
                     各一个 draw call；>150m 楼顶与地标顶部起红色慢闪障碍灯
立面 emis 通道    R=窗光掩码（×族色：玻璃冷白 / 唐楼暖黄）· G=霓虹强度 · B=色相环
```

两个关键决定：

- **泛光只在 HDR 域做、阈值 1.0**：白天混凝土立面（线性 ~0.3）不参与，
  只有窗光（~1.1）/ 霓虹（×1.6）/ 日照水面高光（>2）晕开，白天画面不糊。
- **灯只画"结果"不画"本体"**：万盏路灯若建灯杆模型，几何与 draw call 都会爆；
  空中视角下起识别作用的是地面的光池脉络，灯杆留给 M5 街景级。

## 已知限制

- ~~海面与天空绕过色调映射~~（M4 已解决：全场景统一走 OutputPass 的 ACES+sRGB，
  天空 / 海面调色板经 `fx/tonelink.js` 逆变换为线性 HDR）。
- **`h` 是示意高度，不是实测高度**。为保住 M2 已验收的天际线高度序列，个别地标的高度沿用
  项目既定数值而非公开实测：汇丰总行 60m（实为 179m）、中环广场 181m（实为 374m）、
  IFC 一座 367m（实为 210m）。M3 精建的是**形态语言**（收分 / 塔冠 / 桁架 / 退台），
  高度表未改动。若要按实测校准，只需改 `geo/landmarks.js` 一处 + 同步两份验收断言。
- 建筑仍是体量，没有可进入的室内与街道设施，M5 处理。
- 路灯只有光池与灯头亮点，没有灯杆模型（上帝视角下不足一像素；M5 街景级再补）。
- 降雨区以相机目标为圆心（半径 90m 的雨柱），航拍视角下是一块随镜头移动的局部阵雨，
  不是全港同时降雨。
- 月亮仍是反日位置的示意圆盘（月相 / 真实月轨未做）；时间预设是固定钟点（日落 18:33），
  未跟随季节性的真实日落时刻变化。
- 山腰住宅按等高线近似排布，未做真正的等高线对齐。
- 窗光 / 霓虹是立面贴图内容：贴图每 6 层（一个重复单元）图案相同，但逐实例的整格相位
  平移让相邻同族的楼错开图案，中距已无明显重复感；贴脸细看仍能认出重复单元。

## 坐标系统

- 世界原点：114.159°E, 22.293°N（维港几何中心，青洲以南）
- X 轴向东，Z 轴向南，Y 轴向上；1 单位 = 1 米
- 局部平面投影（等距圆柱），忽略地球曲率
- 比例尺：经度 ≈ 102,999 m/°，纬度 ≈ 110,734 m/°（22.293°N）
